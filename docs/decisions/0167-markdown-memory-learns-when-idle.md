# 0167 · Markdown 记忆：对话停下后提炼，主题按关键词与向量两路浮现

- 状态：proposed / implemented for review
- 日期：2026-11-26
- 关联条款：MEM-002、MEM-004、MEM-006、MEM-011、MEM-012
- 修订：0052 的“提炼只来自 checkpoint”；`_handbook/memory-markdown.md` 的后台提炼与每轮浮现两节
- 实现：extra 仓库 `plugins/markdown_memory/`（12vivi/cable-plugins 分支 `memory/remember-right`、`memory/recall-hybrid`）

## 背景

Markdown 记忆有三处让它记不全、记不准、想不起来：

1. **只从被压缩的对话里学。** 0052 让 included checkpoint 成为唯一提炼来源。压缩要到上下文窗口 74% 才发生，
   空闲预压缩默认只对选中的会话生效（门槛 20 万 token），所以大多数普通长度的对话永远不会进入 `MEMORY.md` 与主题。
   使用规则还告诉 agent“后台会在压缩后提炼，不必重复写”。
2. **提炼规则偏编程场景，且看不到时间。** 提示词重点是陷阱和实测规则，伴侣场景的生活事实、计划、对说话方式的反馈容易漏；
   交给模型的来源消息不带时间，“下周三”无法换算成具体日期。主题文件名只允许 `[a-z0-9-]`，agent 用中文命名的主题会让
   整批草稿因一条写入作废，三次后这段摘要的记忆被跳过。
3. **浮现只靠 BM25 的绝对分数。** idf 随主题总数变化：主题少时命中一两个词的相关主题过不了线，主题多时“需要”这类常见二元组
   单独就能过线；换个说法、中英混用都找不到；一次把整篇主题（最多 3 篇 × 4000 字）塞进上下文并保留到压缩。

对照了几种现行做法：Claude Code 的自动记忆把笔记分为 user / feedback / project / reference 四类，feedback 同时记纠正和被认可的做法，
写入带时间戳，常驻的只有索引、细节按需读（<https://code.claude.com/docs/en/memory>）；Codex、Gemini CLI 等在会话空闲后逐会话提炼；
Zep/Graphiti、Mem0、MemOS 用关键词与向量混合检索再融合排序；LongMemEval 的消融显示按时间扩展查询、给检索键补事实能提升召回。

## 决定

1. **会话停下后提炼。** 新配置 `extract_idle_minutes`（默认 30，`0` 关闭）。空闲巡检每分钟看一次，会话停下后把已闭合、可学习、
   还没学过的完整 Turn 交给与摘要路径同一套提炼、证据校验与幂等写入，来源记为 `idle:<会话>:<最后一条消息>`。
   两条路径在同一把更新锁内各自重读“已学过”：空闲路径的操作与覆盖消息同一事务记入 `idle_learned`，摘要路径据此跳过；
   空闲路径跳过已应用摘要覆盖的消息，被摘要省略的按 MEM-011 也不恢复资格。只补学最近 7 天还有对话的会话；
   连续失败三次的空闲来源记为已处理，原消息保留。
2. **记对东西。** 提炼提示与使用规则按“用户事实 / 对说话与做事方式的反馈 / 计划与约定 / 外部资源去处 / 陷阱与实测规则”组织；
   反馈的纠正和认可都记，写成以后怎么做并带原因；证据不足不记；密码、密钥、证件号、账户号码不记。每条来源消息附上接纳时的
   本地时间与星期，相对日期换算成具体日期。主题文件名与 `[[链接]]` 允许汉字；不合规文件名的主题在提炼提示里标为只读。
   使用规则提醒回忆时只用相关条目，找不到依据就直说记不清。
3. **主题按两路浮现，只注入相关条目。** 关键词通道去掉常见停用词，须命中至少两个不同的词且分数过线。有 embedding provider 时，
   每篇按“文件名 + description”与每条条目分别向量化并缓存；余弦相似度换成相对本次查询无关水平的相关度
   `(s - 基线) / max(1 - 基线, 0.5)`，基线取全部条目与固定参照句的中位数，用与模型无关的 `surface_min_relevance`（默认 0.3）过线。
   两路名次按 RRF 融合；每篇只给最相关的至多 6 条，其余提示用 `read_file` 读。embedding 不可用或失败时记一次降级日志、
   只用关键词（MEM-006）；缓存损坏照常报错。

## 理由

- 空闲提炼复用摘要路径的草稿、证据和 receipt，不新增写 owner；“已学过”与草稿同一事务落盘，两条路径交错、崩溃重放都不会重复学同一 Turn。
- 相对基线的相关度不依赖某个向量模型的分数尺度：常见模型无关文本的相似度从 0.1 到 0.4 不等，绝对门槛无法通用；
  分母设下限，查询与所有内容都相似时也不放大噪声。
- 条目级注入让浮现内容与本条消息相关，并减少保留到压缩前的上下文。

## 未选

- **每轮用模型挑选相关主题**（Claude Code 的做法之一）：每条用户输入多一次聊天模型调用，延迟与费用都高；向量相关度已能覆盖换说法的场景。
- **给 Akasha 情节记忆补事实键**：会改变学习输入，必须先做在线与重放等价验证，留待单独评估。
- **把被摘要省略的消息交给空闲路径补学**：与 MEM-011“省略资料不恢复资格”冲突；正常使用中空闲提炼通常先于压缩发生。

## 代价与恢复

- 每段空闲对话多一次后台模型调用；每条新的用户输入多一次 embedding 请求（与 Akasha 并行），首轮每次最多新算 32 条条目向量。
- 浮现内容随门槛变化；已保存的浮现结果仍按原文回放，前缀缓存不受影响。使用规则文本变化会让各会话的 system 前缀失效一次。
- `markdown-profile-writes.db` 新增 `idle_learned`、`idle_checked`、`surface_vectors` 三张表，只增不改既有表；旧版本忽略它们。
  回退前若还有未应用的空闲草稿，旧版本会因缺少摘要进度拒绝应用，需先用新版本启动一次完成重放。
- `extract_idle_minutes: 0` 恢复为只在压缩后提炼；没有 embedding provider 时只用关键词。

## 验收

- extra 仓库 `tests/markdown_memory/` 启动真实宿主、复制真实插件目录，只替换模型与 embedding 边界：短对话停下后被提炼且只学一次、
  中文名主题可写、来源带本地时间、不合规文件名标为只读；真实压缩摘要与空闲提炼配合时任何消息最多送去提炼一次；关闭后只在压缩后提炼；
  换说法浮现与条目级注入、向量缓存、无关输入不浮现、embedding 故障退回关键词、没有 provider 时只用关键词。
- 真实模型与正式数据上的提炼质量、门槛是否合适，部署后另行核对。
